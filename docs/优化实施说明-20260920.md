# 模型测试程序优化实施说明

## 已实现

- `count_1000`：8192 token、确定性参数、严格连续序号校验；截断后最多整次提升到16384复测。
- `count_5000`：真实 tokenizer 计算5001行标准答案，实际请求额度为标准答案 token 数向上增加10%；49152是客户端允许的预算上限。流式单请求，30秒连接时限、3000秒空闲和总时限；包括网络重试在内至多两次请求，绝不分段拼接。
- `repeat`：忽略空白；仅在 length 结束时接受合法末尾前缀，正确保留 `EXPECTED_TRUNCATED / PASS`。
- `speech`：8192 token，8章节提示；检查正文至少4000汉字、章节1至8完整有序、每章至少450汉字（提示目标550）、拒绝/提纲特征及明显重复。最多3次续写，分别保留单次能力与合并质量。
- 文档翻译：8192→16384单变量额度复测，检查编号顺序、中文残留和完整句尾；无编号且无法机器确认完整性的原文标为REVIEW。按约4000字符分块的业务恢复可选开启；成功块不重试，失败块最多提升一次额度，并受网络重试上限约束；最后仍检查全文。
- 请求前检查上下文、输入长度和服务端输出限制；解析损坏、无效UTF-8、空文档、替换字符或NUL归为DATA_QUALITY。
- 网络超时、连接错误和HTTP 5xx有限指数退避重试；HTTP 4xx不重试。
- JSON、CSV、HTML记录原始/最终结果和恢复动作；报告只引用本次证据，删除固定历史失败结论。

PASS只表示列明的机器规则通过，不代表发言内容正确、翻译语义准确或完整语义覆盖。讲话拒绝与重复检查是启发式规则，内容仍需人工评价。文档检查针对提取后的纯文本显式编号，不解析Word自动编号样式，使用此类文档前应转换为保留编号的文本。

## 真实服务复测前配置

编辑 `automation/config.json`：

1. 将 `endpoint` 指向实际模型服务。
2. 在运行环境安装可加载该模型 tokenizer 的 `transformers`，将**与服务端模型一致**的 tokenizer 文件放在本地，配置例如：

   ```json
   "tokenizer_paths": {"deepseek14b": "D:/Models/deepseek14b"}
   ```

   使用本地文件及模型chat template，不联网下载，不执行远程自定义代码。未配置时，其他用例采用明确标注的UTF-8字节数加模板余量保守估计，可能拦截实际可容纳的请求；`count_5000`必须有真实tokenizer，否则在请求前报CONFIG_LIMIT。精确边界测量也应配置真实tokenizer。
3. 当前配置继续如实保留已知的 `server_limits.max_iter_times=32768`。若实测所需预算超过该值，先将实际服务端改为49152，并根据服务环境调整 `token_timeout`、`e2e_timeout` 至3000，再同步客户端 `server_limits.max_iter_times`。仅修改客户端JSON不会修改服务端能力。
4. 确认后端支持 `min_new_tokens` 后才将 `supports_min_new_tokens` 设为true；程序会对5000序号用例按标准答案实测token数设置最低生成长度。默认不启用 `ignore_eos`。
5. `speech_continuations=0` 可关闭讲话业务续写；最大有效值为3。`translation_chunk_recovery=true` 可开启长文翻译业务分块恢复，默认关闭以优先观察整篇翻译能力。允许保留的中文专名需明确列入 `translation_allowed_chinese_names`，默认不豁免任何中文。

## 证据约定

每个用例的 `*_a1.request.json`、`*_a1.result.json` 和 `*_a1.answer.txt` 保留首次请求；后续尝试使用a2、a3等编号。SSE事件持续保存到对应的events.jsonl。

用例级 `*.result.json` 的 `attempts` 保留全部尝试，`raw_status/raw_quality` 对应第一次，`final_status/final_quality` 对应恢复后。`raw_failure_type/raw_failure_reason`保留原始失败，即使恢复通过也不丢失。`recoverable`表示本次执行过恢复策略，不代表最终成功；以final_quality为准。

`attempt_count`统计实际进入连接阶段的尝试，预检拦截为0。每次预检结果也有证据。累计耗时包含恢复和退避；多次尝试不把最后一次token数当作总体吞吐，逐请求指标可在attempts中查看。

## 验证与运行

在项目根目录运行：

```powershell
& 'D:\Work\Python\conda\python.exe' automation/test_runner.py
& 'D:\Work\Python\conda\python.exe' automation/run_tests.py --dry-run --mode functional
& 'D:\Work\Python\conda\python.exe' automation/run_tests.py --mode smoke --model deepseek14b
& 'D:\Work\Python\conda\python.exe' automation/run_tests.py --mode functional --model deepseek14b
```

本次本地回归及模拟HTTP测试通过，功能预演生成45个用例。真实smoke已尝试，但配置地址127.0.0.1:1025拒绝连接；环境没有transformers及已配置的tokenizer。因此真实小规模生成和完整功能复测尚未完成，不能据此宣称模型已通过优化计划验收。

运行会生成带时间戳的证据目录，并刷新 `模型测评结果/report.html` 固定入口；历史测试仍位于各时间戳目录。
