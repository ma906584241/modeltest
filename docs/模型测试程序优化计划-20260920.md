# 模型测试程序优化计划

## 1. 背景与目标

当前 `deepseek14b` 测试报告共记录 5 个自动质量失败用例：

- `count_1000`
- `count_5000`
- `repeat`
- `speech`
- `doc_2_translate`

本计划用于优化测试程序、请求配置和自动校验，使可恢复问题在后续测试中得到修复，同时保留模型真实能力边界，避免通过放宽标准制造虚假 PASS。

当前报告位置：

```text
modeltest\模型测评结果\report.html
```

主要修改范围：

```text
modeltest\automation\run_tests.py
modeltest\automation\config.json
modeltest\automation\test_runner.py
```

## 2. 实施原则

1. `max_seq_len` 是输入与输出的总上限，不能直接把所有请求的 `max_tokens` 设为 65536。
2. 每个用例使用独立的生成参数和通过标准，不再全部共用 4096 token。
3. 原始模型结果和程序恢复后的最终结果分别记录，不用重试掩盖模型原始能力不足。
4. 只有满足可机器验证的标准才能标记 PASS；超过重试上限仍不满足时必须保留 FAIL。
5. `count_5000` 必须保持单请求、一次性完整输出，不采用分段生成。

## 3. 当前失败原因与优化方向

| 用例 | 当前直接原因 | 归因 | 优化方向 |
|---|---|---|---|
| `count_1000` | 输出到 622 后达到 4096 token 上限 | `CONFIG_LIMIT` | 提高到 8192 token，关闭随机采样，严格校验 0-1000 |
| `count_5000` | 只输出 0、1、2、...、5000，并主动结束 | `CONFIG_LIMIT + MODEL_BEHAVIOR` | 单请求长输出；精确计算目标 token；提高服务端输出上限和超时；抑制提前 EOS |
| `repeat` | 达到预期上限，但严格正则不接受换行和末尾截断前缀 | `VALIDATOR_ERROR` | 修复校验器，正确判定 `PASS + EXPECTED_TRUNCATED` |
| `speech` | 仅生成 1171 个汉字，在 1307 token 时主动结束 | `MODEL_BEHAVIOR` | 强化提示词、提高上限、测试最小生成长度，并增加字数校验和续写兜底 |
| `doc_2_translate` | 输出达到 4096 token 后句中截断，且存在中文残留 | `CONFIG_LIMIT + MODEL_BEHAVIOR` | 提高输出额度；生产流程按章节翻译；校验章节、句尾和中文残留 |

## 4. 统一失败分类与结果字段

测试结果增加以下字段：

```text
failure_type
failure_reason
recoverable
recovery_action
attempt_count
raw_status
raw_quality
final_status
final_quality
```

失败类型统一为：

```text
CONFIG_LIMIT       请求或服务端配置不足
MODEL_BEHAVIOR      模型主动结束、遗漏或不遵循指令
VALIDATOR_ERROR     自动校验规则错误
DATA_QUALITY        原始文档乱码、结构损坏或内容异常
NETWORK_ERROR       连接错误、HTTP错误或超时
```

## 5. 请求前 token 预算检查

每次请求前计算：

```text
prompt_tokens + requested_max_tokens + safety_margin <= max_seq_len
requested_max_tokens <= max_iter_times
```

建议：

```text
max_seq_len = 65536
safety_margin = 1024
```

如果配置不满足条件，在请求前标记 `CONFIG_LIMIT`，不发送必然失败的请求。

## 6. 各失败用例优化方案

### 6.1 count_1000

请求参数：

```json
{
  "max_tokens": 8192,
  "temperature": 0,
  "do_sample": false,
  "repetition_penalty": 1.0
}
```

通过标准：

```text
共识别1001项
第一项为0
最后一项为1000
相邻序号差值为1
无缺号、重号和省略号
finish_reason=stop
```

若仍为 `finish_reason=length`，在上下文允许的前提下提升一级输出额度并完整重测一次。

### 6.2 count_5000：单请求一次性输出

#### 6.2.1 精确计算输出预算

测试程序先构造标准答案：

```text
0 测试
1 测试
...
5000 测试
```

使用 deepseek14b 对应的真实 tokenizer 计算标准答案 token 数：

```text
requested_max_tokens = 标准答案token数 + 10%安全余量
```

预计需要约 36K-40K token，最终以 tokenizer 实测为准。

#### 6.2.2 服务端配置

如果实测超过当前 `max_iter_times=32768`，建议调整为：

```json
{
  "max_iter_times": 49152,
  "token_timeout": 3000,
  "e2e_timeout": 3000
}
```

该用例输入约 54 token，输出即使达到约 40K，总量仍低于 `max_seq_len=65536`。

#### 6.2.3 客户端配置

```json
{
  "stream": true,
  "connect_timeout_seconds": 30,
  "idle_timeout_seconds": 3000,
  "request_timeout_seconds": 3000,
  "max_tokens": 49152,
  "temperature": 0,
  "do_sample": false,
  "repetition_penalty": 1.0
}
```

按照当前约 21.8 token/s 的速度，生成约 33K token 预计需要约 25 分钟，因此现有 600-660 秒超时不足。

流式调用仍属于单次请求、一次完整输出，只是客户端持续接收并保存生成内容。

#### 6.2.4 提示词

```text
这是严格的连续序号输出测试。

请从0开始，逐行输出到5000，格式必须严格为：
0 测试
1 测试
2 测试

硬性要求：
1. 必须完整输出0到5000，共5001行。
2. 不得使用省略号。
3. 不得跳号、重号或提前结束。
4. 不得添加标题、解释、代码块或其他内容。
5. 在输出“5000 测试”之前不得停止。

现在直接从“0 测试”开始。
```

如果 MindIE 接口支持 `min_new_tokens`，根据 tokenizer 实测结果设置最低生成长度。不要默认启用 `ignore_eos=true`，避免完成后继续生成无意义内容。

#### 6.2.5 校验与重试

通过标准：

```python
finish_reason == "stop"
numbers == list(range(5001))
```

同时检查：

```text
无省略号
无附加说明
无缺号和重号
正文以“5000 测试”结束
```

失败时不分段，只允许整次请求重试一次。若 token、超时和最低生成长度均满足后仍提前结束或使用省略号，应保留 FAIL，并明确结论为模型单次长序列指令遵循能力不足。

### 6.3 repeat

校验前移除空格、换行和制表符，然后检查正文是否全部由“测试输出”组成。

当 `finish_reason=length` 时，允许最后一个词语为“测试输出”的合法截断前缀。

通过结果：

```text
status = EXPECTED_TRUNCATED
quality = PASS
```

该用例不再进入模型性能失败统计。

### 6.4 speech

第一次请求仍用于测试模型单次生成能力：

```json
{
  "max_tokens": 8192,
  "temperature": 0.2,
  "do_sample": false,
  "repetition_penalty": 1.03
}
```

提示词要求：

```text
直接输出完整正式发言稿
至少4500个汉字
分为8个章节
每章不少于550个汉字
禁止只给提纲、建议或拒绝语
未达到目标前不得结束
```

单次通过标准：

```text
正文汉字数不少于4000
8个章节完整
无拒绝语和提纲替代
无明显重复灌水
finish_reason=stop
```

如果业务目标要求最终必须交付 4000 字，可增加最多 3 次自动续写。报告必须同时记录：

```text
raw_quality：模型单次结果
final_quality：续写合并后的业务结果
```

### 6.5 doc_2_translate

先进行单变量复测：

```text
第一次：max_tokens=8192
第二档：max_tokens=16384
```

单次翻译通过标准：

```text
finish_reason=stop
所有章节和条款编号齐全
译文以完整句结束
非专名中文残留为0
```

如果生产流程要求稳定完成长文翻译，则按章节或 3000-5000 中文字符组织请求，仅重试失败章节，最终执行全文编号和中文残留检查。报告仍需保留完整文档单次翻译的原始能力结果。

## 7. 自动恢复规则

| 失败现象 | 自动处理 |
|---|---|
| `finish_reason=length` | 有上下文空间时提高 `max_tokens`，否则使用该业务允许的长文处理策略 |
| `finish_reason=stop` 但长度不足 | 强化提示；对允许恢复的业务任务执行续写 |
| 序号缺失、重复或出现省略号 | 判定内容失败；按用例规则进行整次重试 |
| HTTP 5xx 或网络超时 | 指数退避后有限重试 |
| 文档乱码或结构损坏 | 请求前终止，标记 `DATA_QUALITY` |
| 达到重试上限 | 保持 FAIL，记录全部请求证据 |

## 8. 回归测试

需要增加以下自动化回归测试：

1. `repeat` 包含换行和末尾半词时正确判定。
2. `count_1000` 截断时正确分类为 `CONFIG_LIMIT`。
3. `count_1000` 完整输出时严格检查 1001 项。
4. `count_5000` 必须使用单请求，并严格检查 5001 项。
5. `count_5000` 出现省略号、缺号、重号或提前停止时必须失败。
6. `speech` 不足 4000 字时正确记录原始失败和恢复结果。
7. 翻译缺章节、中文残留或句中截断时能够识别。
8. token 总量超过 65536 时在请求前拦截。
9. 达到重试上限后保持 FAIL，不得虚假通过。

## 9. 实施顺序

### 第一阶段：修正基础判定

- 增加失败分类与结果字段。
- 修复 `repeat` 校验器。
- 增加 token 预算预检查。
- 为不同用例增加独立参数。

### 第二阶段：修复功能失败

- 将 `count_1000` 调整到 8192 token。
- 完成 `count_5000` 单请求长输出能力检测、超时调整和严格校验。
- 完成长文发言稿单次测试与续写兜底。
- 完成长文翻译额度复测与完整性校验。

### 第三阶段：回归与交付

- 运行单元测试和模拟响应测试。
- 在真实 deepseek14b 服务上执行小规模验证。
- 执行完整功能复测并核对结果。

## 10. 最终验收标准

优化完成后应满足：

```text
repeat 不再误报失败
count_1000 在合理输出额度下完成严格连续输出
count_5000 保持单请求一次性输出并获得明确、可复现的通过或能力失败结论
speech 同时给出模型单次能力和业务恢复结果
doc_2_translate 能识别截断、章节缺失和中文残留
任何 PASS 均有明确机器校验依据
任何 FAIL 均保留直接原因和请求证据
```

需要特别说明：测试程序可以保证判定准确、恢复策略可控和结果可追溯，但不能保证模型在充分配置后一定完成超出自身能力的任务。如果 `count_5000` 在足够 token、超时和最低生成长度条件下仍提前结束，最终结论应是模型不具备稳定的一次性长序列输出能力，而不是继续放宽校验标准。
