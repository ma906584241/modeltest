# 测评差异修复说明（2026-09-21）

对照此次 `20260920_222757_317054` 与此前固定报告对应的 `20260919_203640_761705`，此次44条结果、此前91条。此次25项CONFIG_LIMIT均为客户端预检拦截，不能解释为模型服务退化。

## 定位与修复

1. 此次sources.json为空，此前有7份业务文档。实际资料位于upload目录，原程序只扫描脚本根目录，因此缺失诗歌翻译1项、文档28项、差异6项、压力12项，共47项。现在支持明确指定data_dir或--data-dir，并自动发现upload；完整测试缺少业务资料时在网络请求前停止，避免静默缩减覆盖。
2. 24个输入/上下文用例被UTF-8字节数估算误拦截，例如8192名义档位被估为49267。字节数不是实测token数，现在默认只警告，由服务端判定；配置真实tokenizer时仍严格检查。可用strict_estimated_preflight恢复保守拦截。
3. count_5000因缺少tokenizer未执行。现在默认在服务端max_iter_times内执行整次测试，明确标注预算不确定，不宣称预算足够，仍严格要求5001行。真实tokenizer可用时继续精确计算。require_count_tokenizer=true可恢复强制要求。
4. 讲话输出使用Markdown加粗章节标题，原正则未识别，错误报告正文汉字0。已支持加粗标题；仍检查章节顺序、每章字数、重复和拒绝内容。
5. 输入边界汇总改用服务端usage.prompt_tokens，并要求自动检查PASS，不再将用例名称中的名义档位作为实测token数。上下文提示移除“只回复输入已接收”和“持续输出”的冲突。
6. 修复报告中被写成问号的中文标签和汇总文字；估算警告进入请求证据、JSON、CSV及HTML。
7. all与full统一包含容量和边界用例。

输入负载仍沿用历史字符构造方式，以保留对照价值；名义档位并非精确token档位。新旧提示词、输出额度、恢复机制和质量规则本来就有变化，质量通过率与耗时不能直接当作同条件性能对比。
